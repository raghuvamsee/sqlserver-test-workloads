# WideWorldImportersDW — Snowflake

Snowflake version of the SQL Server workload in `../`. It is schema-only, like the original.

| File | Contents |
| --- | --- |
| `01_schema.sql` | Database, 8 schemas, 8 sequences, 29 tables with PK/FK constraints and column comments. Generated by `generate_schema.py` from `../schema/`; regenerate with `python3 generate_schema.py`. |
| `02_procedures.sql` | `Integration.GenerateDateDimensionColumns` (SQL UDTF) and 20 of the 24 stored procedures, rewritten in Snowflake Scripting. |

## Deploy

```bash
snow sql -f 01_schema.sql
snow sql -f 02_procedures.sql
```

`01_schema.sql` creates `WIDEWORLDIMPORTERSDW` if missing and uses `CREATE OR REPLACE` for every sequence and table, so re-running it drops existing data.

Then seed the unknown members and dates, the same way as on SQL Server:

```sql
CALL "Application"."Configuration_ReseedETL"();
CALL "Integration"."PopulateDateDimensionForYear"(2013);
```

## Conversion notes

- **Identifiers** keep the original names, quoted and case-sensitive: `[Dimension].[Stock Item]` becomes `"Dimension"."Stock Item"`.
- **Types:** `NVARCHAR(n)` → `VARCHAR(n)`, `DATETIME2(7)` → `TIMESTAMP_NTZ(7)`, `BIT` → `BOOLEAN`, `DECIMAL` → `NUMBER`, `VARBINARY(MAX)` → `BINARY`, `sys.geography` → `GEOGRAPHY`, `sysname` → `VARCHAR(128)`.
- **Keys:** `IDENTITY(1,1)` stays as `IDENTITY(1, 1) ORDER`. `DEFAULT (NEXT VALUE FOR seq)` becomes `DEFAULT seq.NEXTVAL`. Sequences are created with `ORDER` so values keep increasing, as they do in SQL Server.
- **Constraints:** Snowflake records PK and FK constraints but doesn't enforce them.
- **Indexes** (clustered, nonclustered, columnstore) are dropped. Fact tables partitioned on `PS_Date` get `CLUSTER BY` on the same date column.
- **Memory-optimized** `SCHEMA_ONLY` staging tables become `TRANSIENT` tables.
- **Not converted, because Snowflake has no equivalent:** filegroups, `PF_Date`/`PS_Date`, users and permissions, index descriptions, and these procedures: `Configuration_ApplyPartitionedColumnstoreIndexing`, `Configuration_ApplyPolybase`, `Configuration_ConfigureForEnterpriseEdition`, `Configuration_EnableInMemory`.
- **Procedures:**
  - `SET XACT_ABORT ON` is replaced by an explicit transaction plus an `EXCEPTION` handler that rolls back.
  - Correlated `SELECT TOP(1) ... ORDER BY` key lookups become `UPDATE ... FROM` with `QUALIFY ROW_NUMBER()`.
  - `GetLastETLCutoffTime` and `GetLineageKey` return their value directly instead of a result set.
  - `MigrateStagedStockHoldingData` uses `DELETE` instead of `TRUNCATE`, to keep it inside the transaction.
- **`ReseedSequenceBeyondTableValues`:** Snowflake can't `RESTART` a sequence, so the procedure draws values until the next value is greater than the column's maximum.
- **Behavior:** ETL logic otherwise matches the Microsoft sample, including its known quirks. For example, `Configuration_PopulateLargeSaleTable` still marks every `Integration.Lineage` row as complete.
